# بک‌اند نسخهٔ ۱۴ — فیلدهای چندزبانهٔ مستقل

## ساختار واقعی دیتابیس
آبجکت language-first قبلی در MongoDB ذخیره نمی‌شود. هر فیلد چندزبانه مستقیماً آبجکت زبان‌هاست:

```js
{
  name: { en: 'Survey receiver', fa: 'گیرنده نقشه‌برداری', ar: 'مستقبل مساحي', tr: 'Ölçüm alıcısı' },
  brand: { en: 'ComNav', fa: 'کامناو' },
  description: { en: 'Manual description', fa: 'توضیح دستی' },
  tags: { en: ['GNSS'], fa: ['نقشه‌برداری'] }
}
```

- محصولات: name، brand، short_description، description، tags
- فروشگاه‌ها: name و description
- دسته‌بندی‌ها: name
- پلن‌ها: name و description
- کاربران/فروشنده‌ها: firstname و lastname
- اطلاعات ثابت اقلام سفارش: نام و برند به همین ساختار، بدون آبجکت translations

فیلدهای غیرمتنی و اطلاعات تجاری مانند price، stock، شناسه‌ها، دسترسی‌ها، آدرس، پرداخت، حساب تسویه و تاریخ‌ها تغییر نوع نمی‌دهند. برای موارد ناشناخته حذف کورکورانه انجام نمی‌شود.

## API
ورودی ساخت/ویرایش فیلدها را به صورت آبجکت زبان‌ها ارسال کنید. نمونه:
```json
{"name":{"en":"Manual name","fa":"نام دستی"}}
```
ویرایش جزئی فقط همان زبان‌ها را تغییر می‌دهد. مثال پاک‌کردن یک متن دستی:
```json
{"name":{"tr":null}}
```
زبان‌های دیگر باقی می‌مانند و متن محصول/فروشگاه دوباره خودکار پر نمی‌شود.

پاسخ معمولی با `?lang=fa` مقدار نمایشی همان زبان را برمی‌گرداند. برای فرم چندزبانه از `?lang=all` استفاده کنید؛ پاسخ این حالت name.en و name.fa و ... دارد، نه translations.fa.name. fallback خواندن: زبان انتخابی، انگلیسی و سپس اولین مقدار موجود. این fallback متن جدید در دیتابیس نمی‌نویسد.

برای حفظ اعتبارسنجی‌ها و سبک سرویس‌های موجود، مدل یک نمای سازگارِ صرفاً در حافظه به سرویس می‌دهد. تبدیل در `src/model/content.model.js` و توابع مشترک `content-fields.helper.js` متمرکز است. این نمای داخلی در MongoDB یا پاسخ raw API ذخیره/منتشر نمی‌شود. ورودی قدیمی برای سازگاری قابل خواندن است، اما قالب پیشنهادی و خروجی raw فقط field-first است. فرانت نسخهٔ همین بسته را نصب کنید.

## نام و نام خانوادگی، بدون API
`src/utils/helpers/person-name.helper.js` شامل قواعد و جدول نام‌های رایج برای نویسه‌گردانی آفلاین است. مقدار فارسی نام‌هایی مانند علی/رضایی به شکل Ali/Rezaei و شکل عربی و ترکی تکمیل می‌شود. این استثنا فقط برای firstname/lastname است؛ ترجمهٔ خودکار محتوای کاتالوگ همچنان وجود ندارد.

می‌توانید شکل دقیق نام را صریح وارد کنید:
```json
{"firstname":{"fa":"علی","en":"Aly","ar":"علي","tr":"Ali"}}
```
املای دستی موجود بر مقدار پیشنهادی اولویت دارد. با اصلاح یک زبان، شکل‌های موجود دیگر خودکار بازنویسی نمی‌شوند؛ برای اصلاح آن‌ها مقادیر دقیق را صریح ارسال کنید. حساب‌های فروشنده همان رکورد users را دارند و این منطق برای هر دو نوع حساب کار می‌کند. نام هویتی حساب تسویه تغییر نمی‌کند.

نویسه‌گردانی ساده همیشه املای واقعی اشخاص را تشخیص نمی‌دهد. برای نام ناآشنا تبدیل حرفی تقریبی است؛ اگر ورودی لاتینِ ناآشنا باشد، برای فارسی/عربی املای ساختگی با حدس واکه‌ها تولید نمی‌شود و همان شکل لاتین می‌تواند باقی بماند. جدول نام‌های رایج قابل توسعه در خود کد است. هیچ سرویس خارجی، کلید API یا وابستگی ترجمه اضافه نشده است.

## مهاجرت الزامی برای دیتابیس نسخه‌های قبلی
**پیش از روشن‌کردن نسخهٔ جدید روی داده‌های قبلی، از MongoDB پشتیبان بگیرید و نوشتن برنامه را متوقف کنید.** تغییر سورس به‌تنهایی اسناد موجود در سرور شما را تغییر نمی‌دهد.

.env واقعی اتصال سرور را نگه می‌دارد. کلید --source زبان فیلدهای پایهٔ تک‌رشته‌ای قدیمی است؛ آن را متناسب با دادهٔ واقعی انتخاب کنید، نه زبان فعلی رابط.

پیش‌نمایش بدون تغییر:
```sh
npm run migrate:i18n -- --source=fa
```
پس از بررسی گزارش و تهیهٔ پشتیبان:
```sh
npm run migrate:i18n -- --source=fa --apply --backup-confirmed
```

اسکریپت products، categories، stores، plans، users، orders و sub-orders را بررسی می‌کند؛ متن‌های قبلی و دادهٔ غیرمتنی را حفظ و ساختار زبان‌اول را به فیلد‌اول تبدیل می‌کند. فقط نام فیلدهای منسوخِ مشخص یعنی translations، translation_status و store_translations حذف می‌شوند؛ مورد سوم در صورت داشتن نام فروشگاه به store_name زبان‌دار تبدیل می‌شود. متن اصلیِ مستقل نیز با زبان مبنای انتخاب‌شده، در صورت نبود تعارض، حفظ می‌شود. قیمت و مبلغ سفارش تغییر نمی‌کنند.

conflicts باید صفر باشد. تعارض متن قدیمی/جدید گزارش و کل آن سند بدون تغییر رها می‌شود؛ خروجی فرایند ۲ است. update_at نیز برای تشخیص تغییر هم‌زمان بررسی می‌شود، اما جای توقف نوشتن برنامه و پشتیبان را نمی‌گیرد. برای داده‌های مبنای مخلوط ابتدا زبان واقعی/تعارض‌ها را جداگانه بررسی کنید؛ یک --source را کورکورانه روی چند مبنای متفاوت اجرا نکنید.

دوباره پیش‌نمایش بگیرید؛ بعد از مهاجرت موفق changed=0 و conflicts=0 انتظار می‌رود. سپس برنامه را روشن کنید. مهاجرت خودکار هنگام startup و حذف تخریبیِ بی‌تأیید انجام نمی‌شود. مهاجرت روی دیتابیس آزمایشی واقعی MongoDB بررسی شده، نه دیتابیس سرور شما.

## اجرا و نصب
Node.js 20.19+ یا 22.12+ و MongoDB لازم است.
```sh
npm ci
npm run setup
npm run check:imports
npm start
```
setup فایل env موجود را بازنویسی نمی‌کند. سورس را در پوشهٔ تمیز استخراج و env/آپلودهای شخصی را برگردانید. ابتدا طبق بخش قبل دادهٔ قدیمی را مهاجرت دهید، سپس بک‌اند را restart و فرانت هم‌نسخه را build کنید.

قیمت کاتالوگ USD، نرخ معتبر TGJU، نمایش انتخابی ارز و مبلغ قفل‌شدهٔ سفارش/پرداخت IRR حفظ شده‌اند. API نرخ ارز همچنان برقرار است؛ API ترجمهٔ محتوا وجود ندارد. ساختار module/controller/service/middleware/routes و model/controller حفظ شده و فایل یا وابستگی تست بک‌اند داخل سورس تحویلی نیست.
